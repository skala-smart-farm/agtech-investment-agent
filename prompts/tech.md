작성 규칙
- 모든 주장 끝에 근거 id 를 대괄호로 붙인다. 예: "병해충 인식 정확도 95% [W1a2b3]"
- 근거가 없는 내용은 쓰지 말고 "확인 불가"라고 쓴다. 회사 홍보 문구는 사실 주장으로 옮기지 말고 "회사 측 주장"이라고 밝힌다.
- 문서 근거([D...])는 분야 전체의 기술 동향·상용화 수준을 설명할 때 쓰고, 회사 고유 사실에는 쓰지 않는다.
- 웹 근거의 "(본문)" 줄은 기사 본문에서 가져온 문단이다. 창업자 이름·학력·경력은 대개 여기에 있으니 끝까지 읽어라.
- maturity: 연구(논문·개발 중) / 시제품 / 실증(시범 농가·파일럿·PoC) / 상용(유료 판매·계약) / 확인 불가
  - "오는 10월 상용화", "내년 출시"처럼 앞으로의 계획은 현재 성숙도가 아니다. 가장 최근 날짜의 근거로 현재 상태를 정하고, maturity_evidence 에 그 날짜와 계획(예정)을 구분해 쓴다.
- founders: 근거에 이름이 나온 이 회사의 대표·공동창업자·기술 책임자(CTO·기술이사·연구소장).
  - 근거에 "○○○ 대표", "(대표 ○○○)", "○○○ CTO" 같은 표현이 있으면 반드시 넣는다. 위 프로필의 대표자 이름이 근거에도 나오면 그 사람을 넣는다.
  - background 에는 근거에 적힌 학력·경력·이전 창업을 그대로 요약하고 근거 id 를 붙인다. 근거에 없으면 "확인 불가".
  - evidence_ids 에는 그 이름이 실제로 나오는 근거 id 를 넣는다. 다른 회사 사람, 투자사·기자·연구원은 넣지 마라. 근거에 이름이 없으면 빈 목록.
- growth_signals: 회사 성장 신호를 2~5개. 수상, 정부·기관 선정, 투자 유치, 상용화·출시 일정(예정이면 "예정"), 인력 규모(국민연금 가입자 수 등).
  각 항목에 날짜와 근거 id 를 붙인다. 형식: "<YYYY-MM> <사건> [근거 id]". 근거가 없으면 빈 목록.
- 간결하게. 각 항목 1~3문장.

- 근거가 영어여도 **출력은 모두 한국어**로 쓴다.
